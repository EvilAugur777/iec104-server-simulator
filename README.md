# IEC 60870-5-104 Load Simulator

Легковесный автономный симулятор сервера (Slave) протокола **МЭК 60870-5-104** на чистом Python для нагрузочного тестирования SCADA-систем (проверено на MasterSCADA 4D).

Не требует установки сторонних библиотек — работает на стандартном стеке Python 3 под Linux и Windows.

---

## 📦 Состав проекта

В репозитории представлены две версии генератора под разные сценарии тестирования:

| Файл | Особенности работы | Когда использовать |
| :--- | :--- | :--- |
| **`iec104_sim.py`** | Генерирует новые случайные значения (`Float`) для всех тегов на каждом такте. Упаковка 50 000 тегов занимает **~40 мс**. | Для проверки визуального обновления данных в интерфейсе SCADA и наглядной проверки связи. |
| **`iec104_sim_fast.py`** | Предварительно формирует пакеты в памяти при старте. Отправка 50 000 тегов занимает **~3–5 мс**. Значения тегов статичны, обновляется только метка времени и счетчик цикла в первом теге (`START_IOA`). | Для поиска предельной пропускной способности драйвера SCADA без упора в производительность генератора. |

## ⚙️ Конфигурация параметров

Основные настройки задаются в начале скрипта:

```python
HOST = '127.0.0.1'   # IP-интерфейс сервера ('127.0.0.1' — только локально, '0.0.0.0' — принимать внешние подключения)
PORT = 2404          # TCP-порт сервера МЭК-104
CA = 1               # Общий адрес станции (Common Address / АСДУ)
START_IOA = 1        # Начальный адрес объекта информации (IOA)
TAG_COUNT = 50000    # Количество генерируемых тегов (тип M_ME_NC_1 / Float)
BATCH_SIZE = 30      # Количество тегов в одном TCP-кадре (макс. 30 для Float, чтобы не превысить лимит APDU в 255 байт)
PERIOD_SEC = 0.20    # Период отправки пачки в секундах (0.1 = 100 мс, 0.2 = 200 мс)

# Папка для сохранения минутной статистики (в Windows создастся в корне текущего диска)
LOG_DIR = '/tmp/iec104_sim_logs'
```

## 🚀 Запуск

**Требования:** установленный **Python 3.7+** (внешние пакеты через `pip` не нужны).

### Linux (Astra Linux / Ubuntu / Debian)
Если файл редактировался в Windows, перед первым запуском очистите переносы строк формата `CRLF`:
```bash
sed -i 's/\r$//' iec104_sim.py iec104_sim_fast.py
```

Запуск стандартной или быстрой версии:
```bash
python3 iec104_sim.py
# или
python3 iec104_sim_fast.py
```

### Windows
```cmd
python iec104_sim.py
:: или
python iec104_sim_fast.py
```
> **Примечание:** При первом запуске в Windows разрешите доступ для Python в окне Брандмауэра, чтобы не блокировать порт `2404`.

## 📊 Мониторинг и логирование

Симулятор отслеживает прикладные подтверждения приема от SCADA (**S-кадры** протокола МЭК-104), что позволяет видеть реальную очередь необработанных данных внутри клиента:

1. **В консоли (раз в секунду):** выводится время отправки пачки, общее число подтвержденных SCADA тегов и текущий размер очереди необработанных пакетов.
2. **В файле лога (раз в минуту):** статистика автоматически сохраняется в `/tmp/iec104_sim_logs/stats.log` (или `stats_fast.log`).

Пример записи в логе:
```text
2026-11-16 11:25:00 | Подтверждено за мин: 15000000 (250000 тег/сек) | Всего подтверждено: 45000000 | Всего отправлено: 45050020 | Очередь в SCADA: 50020
```

* **Норма:** значение `Очередь в SCADA` держится на уровне одного отправляемого пакета (`~TAG_COUNT`) и не растет со временем.
* **Перегруз клиента:** значение `Очередь в SCADA` непрерывно увеличивается от минуты к минуте.
